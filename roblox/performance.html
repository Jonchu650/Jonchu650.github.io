§ 07  ·  Metrics

Performance

A crash and a bounce are the same event as far as the algorithm is concerned. This is the dashboard where engineering problems become ranking problems.

Why this page sits alongside the metric pages

First play bounce rate is the second-most-important ranking signal, and it is measured in two buckets — under 60 seconds, and 61–180 seconds. A large share of under-60-second exits on any given game are not creative failures at all. They are slow loads, out-of-memory kills on low-end Android, and first-frame breakage. Performance work is retention work.

01Access and layout

Creator Hub › Creations › your game › Monitoring › Performance. The header shows current users, server count and device breakdown immediately; the client and server charts require 100+ DAU.

Two tabs, Client and Server, plus date range and interval controls, and a Place menu to examine individual places rather than the whole universe.

Reading percentiles

If P90 server heartbeat is 59, then 90% of your servers run at or below 59 FPS. If P10 is 40, the worst 10% of servers are at or below 40 FPS. P50 is the median. Your P10 client frame rate is the number that describes the experience of the players most likely to leave.

Dashed lines mean do not trust the number

When ended sessions are low, crash rate breakdowns become unstable and the chart draws a dashed line instead of a solid one. That is Roblox telling you the data point is noisy. Check total crash count instead of crash rate when you see it — otherwise you will chase a 40% crash rate that represents two sessions.

Drilling into a spike

The CPU and memory charts default to an Overall view but have dropdowns for individual process groups — physics, rendering, scripts and so on. The category names map directly onto the MicroProfiler's groups, so when you spot a suspicious process on the dashboard you can take a server dump, switch to Timers mode, and filter by that same group name to find it.

Memory tags map onto Enum.DeveloperMemoryTag, with one exception: CoreMemory:Total corresponds to Internal. Use the Developer Console's memory view to chase a specific tag — if the dashboard shows PlaceMemory:GraphicsTexture climbing, that is where you look.

One caveat Roblox flags: the sum of the process categories is not comprehensive. The server does a small amount of uncategorised work each frame, so overall values read slightly low. Close enough to act on, not exact.

Currently only available to a small number of top games, but the principle generalises to everyone: the first 60 seconds should be spent streaming assets and nothing else. Every inventory lookup, leaderboard fetch or friends query you fire on PlayerAdded is competing with your own load time — which is competing with your under-60-second bounce rate, which is the second-most-important ranking signal. Defer anything the player cannot see yet.

05The performance response protocol

  1. Check recent updates. If the impact is severe, roll back first and diagnose after.
  2. Break down by place version to confirm the regression belongs to your new build and not to a platform release.
  3. Break down by platform, OS and memory group to find who is actually affected.
  4. Use the built-in tools — Developer Console for errors, logs, memory and networking; Script Profiler for expensive scripts; MicroProfiler for a visual frame breakdown.
  5. Ask your community. Players reproduce device-specific bugs you never will.

06The pre-publish checklist

  • Tested on a phone, not just in Studio — ideally a cheap Android one
  • Client CPU time under 16 ms on your target device tier
  • Server memory flat over a server's lifetime, not climbing
  • No heavy API calls fired on player join
  • Client memory usage percentage well clear of 100% on the lowest memory group you support
  • Crash rate and OOM exits checked against the previous place version after every publish
  • Error report reviewed — a silent script error can be costing sessions
